Maintenance

Saved policy applies to subsequent refresh batches and survives restarts. Provider retention is only a hint, not a durability guarantee. Results below are per batch; continued batches have separate jobs. A done batch with blocked, failed or unrecoverable counts is not healthy. Orphan cleanup removes only local chunk/article metadata, never NNTP articles. All historical, conflict and deleted versions stay protected. Cleanup refuses accounts with incomplete references; an unlocked upgraded client must backfill every legacy revision first.

Explicit opt-in: successful cleanup permanently requires reference-aware version commits for this account, even if zero chunks are removed. Upgrade all clients first. Upload/reuse older than the grace period may fail safely and require retry. One run collects at most 1000 chunks; run again for further batches.

Provider edits do not require a restart. Restarting interrupts active transfers.
